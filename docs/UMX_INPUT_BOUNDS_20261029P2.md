# UMX 输入范围检查修复

版本：`2026.10.29p2`。本轮修正 UMX 容器的范围检查，继续保留此前已验证的末端延拓、零前缀、混音算法和原 Reader ABI。

## 原因与改动

固定 libmodplug 0.8.9.0 的 `load_umx.cpp` 在遍历名字表时，从 `name_offset + 相对偏移` 固定复制一段数据，没有先验证剩余输入长度。导出记录、紧凑索引、音乐对象和类型签名的读取也依赖未统一检查的偏移。已有私有负对照记录表明，错误名字表偏移会导致访问异常，而不是正常返回“文件格式无效”。

新增 `src/umx_reader.cpp` 实现有范围检查的读取游标；CMake 用它替换固定上游的 UMX 加载器。每次读取前验证 `position <= size` 和 `count <= size - position`，避免先做可能溢出的加法。具体包括：

- 头部字段、名字表索引和每条名称的长度／终止符。
- 紧凑整数的最大字节数、合法末字节和有符号范围。
- 导出对象的位置、声明长度与实际音乐数据长度。
- IT／S3M／XM／MOD 签名的实际可读范围。

继续使用固定上游支持的版本、首个音乐导出对象和类型规则，保留部分包将 IT 标成 S3M 的兼容分支。没有把偏移检查失败后的字节当作正常音乐，也没有改变模块混音、时长、定位或标签逻辑。

这不是完整 Unreal Package 实现；其它对象类型、多对象选择、更高版本及可选现代 libopenmpt 后端没有因此扩展。

## 验证

所有样本、探针和结果只保存在私有 `rebuild/tests/plugins_followup_20261029p2/mod`，不进入 Actions 或发行包。

父任务采用普通 Reader 接口执行独立的 `publicstage/run.cmd`：

| 组别 | 数量 | 验收条件 |
| --- | ---: | --- |
| 支持版本与音乐类型组合 | 60 | 完整 PCM 与既有参考哈希一致，保持时长、EOF 和定位行为 |
| 不合法容器边界 | 36 | Open 正常返回失败；同一 Reader 随后仍可打开有效文件 |
| 既有八格式样本、不同容量、并发与定位隔离 | 15 | PCM、缓冲区边界和 Reader 隔离保持不变 |
| 合计 | **111** | `MOD_PUBLIC_CASES=111 FAILURES=0` |

Windows 11、XP SP3、Win7 SP1 使用同一最终 DLL，分别 **111/111** 通过。该验收入口不加载原版 DLL，不调用内部函数，也不使用内存保护区探针。较早子任务保存的底层观察与这套公开接口验收分开记录，不把它们重复累加为三系统用例。

真实 `ASP-Botmca9.umx`、两个 XM 和其它既有格式的完整 PCM 均保持本轮修复前的基线。原版未初始化采样前缀仍不模拟；此前所测 UMX 的逐字节一致性未回退。
